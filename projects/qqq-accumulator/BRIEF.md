QQQ 장기 적립 자동 매수 프로그램을 만든다.

[이번 구현 범위]
원래 구현 순서의 1~2단계만 구현한다.
1. 백테스트와 기준선
2. 주문 상태 관리와 FakeBroker (안전 장치, 보유 수량 대조, 알림 인터페이스 포함)

증권사 어댑터, 텔레그램 전송, OS 스케줄 등록은 다음 단계이며 이번에는 만들지 않는다.
이번 단계의 주문 흐름은 Broker 인터페이스와 FakeBroker로 구현하고 검증한다.
알림은 Notifier 인터페이스와 테스트용 FakeNotifier까지 만든다.

[목표]
미국 ETF QQQ의 보유 주수를 장기적으로 늘린다. 프로그램은 일봉 데이터로 규칙을 판단해 매수 주문을 자동 실행한다.
성과 지표는 수익률이 아니라 같은 입금액으로 모은 최종 주수다.

[사용자 결정값]
- 증권사: 아직 정하지 않았다. 이번 범위는 FakeBroker만 쓴다.
- 이 프로그램 전용 계좌 사용: 아직 정하지 않았다. 이번 범위는 아래 [주문]대로 증권사 주문가능금액을
  사용 가능 현금으로 쓴다. 공유 계좌로 정하면 예산 장부 방식을 정한 뒤 별도 요구사항으로 추가한다.
- 시험할 규칙 R1·R2: 아직 정하지 않았다. 이번 범위의 규칙 파일은 기준선과
  "종가가 X달러 이하일 때 사용 가능 현금 전액 매수" 형태(동작 예시 2)만 지원한다.
  R1·R2가 정해지면 필요한 지표를 그때 추가한다.
- 아래 숫자 결정값은 설정 파일의 필수값이며 기본값을 두지 않는다. 값이 없거나 형식이 틀리면
  그 값을 쓰는 명령은 주문 없이 오류(종료 코드 2)로 끝난다. 테스트는 [동작 예시]의 값을 쓴다.
  - 백테스트 입금: 주기, 금액, 통화(KRW 또는 USD)
  - 안전 한도: 1회 달러, 월 달러
  - 비용: 매수 수수료 %, 환전 비용 %, 배당 원천징수 %
  - 주문 시간대: 뉴욕 시각 시작~끝 (증권사의 LOC 접수 마감 이전)
  - 지정가 여유: 직전 종가의 %
  - 이상 가격 기준: 직전 종가 대비 ±%
  - 소수점 수량 지원 여부 (증권사가 정해지면 그에 맞춘다)
  - 채택 기준: 미리 떼어 둔 평가 구간 연수, 그 구간에서 기준선보다 최종 주수가 많아야 하는 비율 %,
    시작 월을 바꾼 구간의 연수, 그중 기준선 이상이어야 하는 구간 비율 %
  - paper 통과 기준: 보유 수량 불일치 0건, 미해결 주문 0건을 유지해야 하는 연속 거래일 수
- 운영 환경: macOS에서 운영한다(Linux도 가능). 시간 판단은 표준 라이브러리 zoneinfo의
  America/New_York을 쓴다. 시간대 데이터가 없는 환경(예: Windows 기본 Python)에서 run은
  주문 없이 오류(종료 코드 2)로 끝난다. 데이터 가져오기와 백테스트는 시간대 없이 동작한다.

[기준선]
정해진 입금일에 판단해 다음 거래일에 사용 가능한 현금 전액을 매수한다. 모든 규칙을 이 기준선과 비교한다.
어떤 규칙도 채택 기준을 넘지 못하면 기준선을 운영 규칙으로 쓴다.

[기술 제약]
- Python 3.11 이상, 표준 라이브러리만 사용한다. 테스트는 unittest로 작성한다.
- 저장소는 SQLite 파일 하나다 (WAL 모드, STRICT 테이블).
- 메시지 큐, DB 서버, 상주 데몬, 웹 UI를 만들지 않는다. OS 스케줄러가 15분마다 단발 프로세스를 실행한다.
- 판단 경로에 LLM 호출이나 차트 이미지 분석을 넣지 않는다.
- 금액과 수량 계산에 float를 쓰지 않는다. 지표 계산은 예외다.
- 이 제약을 벗어나야 하면 구현을 멈추고 질문한다. 질문에는 관련 요구사항, 측정값 또는 재현되는 실패, 현재 구성과의 수치 비교, 기각한 대안을 포함한다.

[데이터]
- 일봉마다 원시 시가, 고가, 저가, 종가, 거래량, 분할 계수, 주당 배당금을 저장한다.
- 배당 조정 가격으로 주수를 계산하지 않는다. 배당과 분할은 별도 이벤트로 처리하고, 지표는 분할만 조정한 가격으로 계산한다.
- 백테스트 데이터는 CSV 스냅샷으로 가져오고, 파일 해시를 결과에 기록한다.
- 날짜 중복, 거래일 누락, 0 이하 가격이 있으면 가져오기를 거부한다.

[백테스트]
- 운영과 백테스트는 같은 판단 코드를 쓴다. 봉을 날짜순으로 하나씩 넘기고 지표는 증분 계산한다. 봉마다 과거 구간을 복사하거나 다시 계산하지 않는다.
- T일 종가로 판단한 주문은 T+1일 LOC로 시뮬레이션한다. T+1일 종가가 지정가 이하면 종가로 전량 체결하고, 아니면 미체결로 처리한다.
- 수량은 주문 시점에 지정가 기준으로 고정한다. 소수점을 지원하지 않는 증권사면 정수로 내림하고, 남은 현금은 이월한다.
- 입금 통화가 KRW면 일별 환율 CSV로 USD 입금액을 계산한다.
- 매개변수를 조정한 구간과 평가 구간을 분리한다.
- JSON으로 출력한다: 규칙별 최종 주수, 남은 현금과 마지막 종가 기준 환산 주수, 총 입금액, 평균 매입 단가, 현금 대기 일수, 미체결 횟수, 기준선 대비 차이.

[주문]
- 매수 전용이고 종목은 QQQ로 고정한다. 매도 함수를 만들지 않는다.
- 주문 유형은 LOC이고, 지정가는 직전 종가 × (1 + 지정가 여유)다.
- 주문 금액은 규칙 금액, 주문가능금액, 1회 한도, 월 한도 잔액 중 가장 작은 값이다. 규칙이 쓰는 사용 가능 현금은 운영에서는 증권사 주문가능금액이고, 백테스트에서는 시뮬레이션 잔액이다.
- 거래일과 규칙 조합당 주문은 1건이며 DB UNIQUE 제약으로 보장한다.
- 증권사 전송 전에 주문 의도를 SENDING 상태로 커밋한다. 타임아웃이나 크래시로 결과를 모르면 재전송하지 않고 증권사 주문 내역으로 확인한다.
- 매 실행은 미완료 주문과 보유 수량을 증권사와 대조하는 것부터 시작한다.
- 시간 판단은 모두 America/New_York 기준이다. 거래일과 조기 폐장은 달력 데이터로 판단한다.
- 키는 환경 변수로만 받는다. 키와 토큰은 로그, DB, 알림에 남기지 않는다.

[운영 단계]
- dry-run, paper, live 순서이며 기본값은 dry-run이다. 단계 변경은 사용자가 설정 파일에서 직접 한다.
- 프로그램과 AI 코딩 에이전트는 단계를 올리지 않고, 실계좌 키에 접근하지 않으며, 실계좌 주문을 실행하지 않는다.
- HALT 파일이 있으면 어느 단계에서든 주문을 보내지 않는다.
- 이번 범위의 가정(사용자 확인 필요): dry-run은 대조·판단·안전 장치 확인과 주문 의도 기록까지 하고
  증권사로 주문을 보내지 않는다. 이번 범위에는 실제 증권사 어댑터가 없으므로 paper·live 단계의 run은
  주문 없이 오류(종료 코드 2)로 끝난다. 주문 흐름 전체는 FakeBroker 테스트로 검증한다.

[알림]
- 거래일마다 결과 요약을 1건 보내고, 주문이 없는 날도 보낸다. 메시지가 오지 않으면 사용자가 장애를 알아챌 수 있게 하기 위해서다.
- 오류와 안전 장치 작동은 즉시 보낸다. 알림 실패가 주문 상태를 바꾸면 안 된다.
- 실제 전송 수단은 텔레그램 봇이며 다음 단계에서 붙인다. 이번 범위는 Notifier 인터페이스와 FakeNotifier다.

[CLI]
- import-data --file CSV
- backtest --rules 파일: 결과 JSON 출력
- run: 1회 실행. 종료 코드 0은 정상, 1은 안전 장치로 주문하지 않음, 2는 오류
- status: 누적 주수, 평균 단가, 최근 주문, 중단 사유
- adjust --shares N --reason 사유: 보유 수량 차이 기록

[동작 예시: 모두 테스트로 만든다. 금액은 테스트 값이다]
1. 100달러를 1, 3, 5번째 거래일에 입금하고 종가가 100, 100, 50, 50, 100, 100이며 수수료 0, 지정가 여유 0%, 소수점 허용이면, 기준선은 2, 4, 6번째 거래일에 1 + 2 + 1 = 4주를 산다.
2. 같은 데이터에서 "종가 60달러 이하일 때 전액 매수" 규칙은 4번째 거래일에 4주를 산다. 결과는 최종 4주, 현금 100달러, 환산 5주로 보고한다.
3. T+1일 이후 가격을 임의로 바꿔도 T일까지의 판단 목록은 같다.
4. 2:1 분할(실제 사례: QQQ 2000-03-20)이 있으면 보유 주수가 2배가 되고, 약 50% 가격 변화는 하락 신호로 쓰이지 않는다.
5. 2026-11-05에 직전 종가 100달러, 지정가 여유 2%, 사용 가능 현금 500달러, 수수료 0, 소수점 미지원, 규칙 금액 500달러면 지정가 102달러로 4주 LOC 1건을 전송한다.
6. 5번 주문의 당일 종가가 98달러면 4주가 392달러에 체결되고 108달러가 남는다. 종가가 103달러면 미체결이고 같은 날 재주문하지 않는다.
7. 같은 거래일에 다시 실행하면 주문 전송은 0회다.
8. 전송 직후 프로세스가 죽어 SENDING 상태가 남으면 다음 실행이 주문 내역을 조회한다. 일치하는 주문이 있으면 연결한다. 없으면 UNKNOWN으로 두고 재전송 없이 알린다. 장 마감 후 내역과 잔고로 확정하기 전에는 새 주문을 내지 않는다.
9. 1회 한도 300달러, 규칙 금액 500달러, 지정가 102달러면 2주만 주문하고 경고를 보낸다. 월 한도를 다 쓰면 주문하지 않고 알린다.
10. 주문가능금액 50달러, 지정가 102달러, 소수점 미지원이면 주문 없이 알린다.
11. DB 10주, 증권사 11주면 신규 주문을 중단하고 알린다. adjust로 사유를 기록해야 재개한다.
12. 휴장일, 달력 정보가 없는 날, 최신 봉이 직전 거래일이 아닌 경우, 분할 기록 없이 이상 가격 기준을 넘은 경우, HALT 파일이 있는 경우에는 주문 전송 0회이고 사유를 기록한다.
13. 주문 시간대가 뉴욕 시각 15:30을 포함하면 2026-10-30 15:30 ET(10-31 04:30 KST)와 2026-11-02 15:30 ET(11-03 05:30 KST)를 모두 주문 시간대로 판단한다.
14. (다음 단계, 증권사 어댑터와 함께) 인증 오류가 나면 토큰 재발급을 1회만 시도한다. 테스트 로그 어디에도 키 문자열이 없다.
15. 기본 테스트는 네트워크 없이 FakeBroker로 실행한다.

[다음 단계로 미룬 것]
- 증권사 어댑터. 증권사를 정하면 원래 brief의 해당 증권사 제약(한국투자증권: TR·주문구분·거래소 코드·토큰 캐시·배당과 분할 데이터 출처 질문, 토스증권: 공식 openapi.json 확인 항목)을 다음 단계 요구사항으로 옮긴다.
- 텔레그램 전송, OS 스케줄 등록(macOS launchd 등), 동작 예시 14.
- 공유 계좌의 예산 장부, R1·R2 지표.

[제외 범위]
매도, 공매도, 신용과 미수, 레버리지 ETF, QQQ 외 종목, 분봉 매매, 웹 대시보드, 환전 자동화, 세금 신고.
